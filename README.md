# Single-Cell RNA-Seq Downstream Analysis Pipeline

A fully containerized, production-ready pipeline for processing and analyzing high-throughput single-cell RNA transcriptomic data. This workflow handles everything from programmatic data retrieval to quality control, log-normalization, dimensionality reduction (PCA & UMAP), graph-based clustering, and functional enrichment analysis. 

The pipeline reproduces and structures downstream analysis based on single-cell molecule (UMI) counts from human induced pluripotent stem cells (iPSCs) published by **Tung et al. (2017)** to study batch effects.

## Project Architecture

The codebase is strictly modularized to isolate specific stages of the bioinformatic workflow:

```
scrna-seq-pipeline/
├── data/                  # Git-ignored: Holds raw input matrices from publication
├── results/               # Git-ignored: Holds generated CSVs and analytical outputs
├── scripts/
│   ├── data_loader.R      # Data ingestion, file downloading, and cell identity alignment
│   ├── qc_normalize.R     # Outlier cell filtering (mitochondrial/feature thresholds) & normalization
│   ├── dim_reduction.R    # High-variable feature selection, scaling, PCA, and UMAP execution
│   ├── clustering.R       # Shared Nearest Neighbor (SNN) graph clustering & marker discovery
│   └── enrichment.R       # Functional Enrichment Analysis via gprofiler2 (GO:BP)
├── main.R                 # Core orchestrator script verifying paths and managing execution flow
├── Dockerfile             # Container definition compiling system dependencies and Seurat binaries
├── docker-compose.yml     # Orchestration layer managing host-to-container volume mappings
└── .gitignore             # Prevents raw data datasets and session files from entering version control
```

## How It Works (Data & Volumes)

To keep your local system clean, R and its extensive biological packages are isolated entirely inside the Docker container.

The project uses Docker Bind Mounts via Docker Compose to link your local directories to the container at runtime:

- `./data` maps to the container's raw data directory. The pipeline checks this folder first. If empty, it programmatically downloads the dataset directly onto your hard drive.

- `./results` maps to the output directory. All tables, identified cell markers, and functional pathways generated by the pipeline are compiled and written directly into this folder on your host machine.

### Step 1: Clone the Repository

Clone this repository to your local machine and navigate into the root directory:

```bash
git clone [https://github.com/yourusername/scrna-seq-pipeline.git](https://github.com/yourusername/scrna-seq-pipeline.git)
cd scrna-seq-pipeline
```

### Step 2: Build the Container Image

Compile the isolated container environment. This step downloads the base R runtime and installs required system libraries (`libssl`, `libxml2`, etc.) and R documentation bundles (`Seurat`, `gprofiler2`, `dplyr`):

```bash
docker compose build
```

### Step 3: Execute the Pipeline
Spin up the pipeline worker container. This will automatically set up your local directories, verify connections, ingest or download the matrices, run the processing scripts, and save the results back to your machine:

```bash
docker compose up
```

Once the terminal logs output `=== Pipeline Run Completed Successfully ===`, the container will automatically stop and clean itself up.

## Expected Outputs
After a successful run, your local project directories will populate with the following persistent files:

```
├── data/
│   ├── molecules.txt                    # Raw UMI single-cell count expression matrix
│   └── annotation.txt                   # Correct cell annotations and batch identifiers
└── results/
    ├── cluster_markers.csv              # Statistically significant marker genes per identified cluster
    └── functional_enrichment_cluster0.csv # GO:Biological Process pathways enriched in Cluster 0
```
